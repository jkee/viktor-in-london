# Viktor in London

A personal map of London for answering one question: **where do I want to live?**

Live at **[viktor-in-london.uk](https://viktor-in-london.uk)**.

Two signals meet on one map. The subjective one: scored voice notes recorded
while walking the city, shown as colored dots. The computed one: a liveability
heat surface (red = amenity desert, green = everything at your doorstep)
blending connectivity, coffee, food and daily-life amenities — methodology in
[docs/livability.md](docs/livability.md). Around them sit reference layers —
specialty coffee, casual restaurants rated 8.0+, stations, "good life" chains,
and a violet crime-severity overlay — all scoped to roughly TfL Zones 1–2.

## Running locally

It's a fully static site — no build step, no dependencies to install.

```bash
python3 -m http.server 8741
```

Then open <http://localhost:8741>. (Opening `index.html` directly also works;
internet is needed for map tiles, Leaflet, and the web font.)

## Project structure

```
index.html                    page shell: panel, toggles, script includes
about.html                    public "about the data" page
css/style.css                 all styling (panel, badges, popups, Leaflet chrome)
js/app.js                     map logic: canvas layers, marker layers, controls
data/
  notes.js                    walk notes (the personal data) → window.NOTES
  zone.js                     area-of-interest polygon        → window.ZONE
  coffee-chains.js            chain cafe locations            → window.COFFEE
  coffee-independents.js      independent cafes (appended)    → window.COFFEE
  food.js                     restaurants rated 8.0+          → window.FOOD
  stations.js                 tube/rail stations              → window.STATIONS
  wealth.js                   "good life" chain markers       → window.WEALTH
  crime.js                    crime density per LSOA          → window.CRIME
img/
  apple-touch-icon.png        the VIKTOR roundel (favicon / home-screen icon)
docs/
  data-sources.md             where each dataset came from & how to refresh it
  livability.md               heat-map formula & constants (single source of truth)
  deployment.md               Railway + Cloudflare setup and how to deploy
Dockerfile                    Caddy static file server (used by Railway)
```

Each `data/*.js` file is a plain array assigned to a `window.*` global —
deliberately low-tech so entries can be edited by hand or regenerated by script.

## Editing the data

**Add a walk note** — append to `data/notes.js`:

```js
{ lat: 51.5465, lng: -0.1058, score: 4, note: "Quiet, leafy, felt like home.", date: "2026-09-01" }
```

`score` runs from −5 (no way) to +5 (love it) and colors the dot.

**Change the area of interest** — edit the `[lat, lng]` ring in `data/zone.js`.
Each vertex has a comment naming the place it passes through. The zone draws the
dashed border, dims everything outside, and is the filter used when datasets
are (re)generated — see `docs/data-sources.md`.

**Add a cafe / restaurant / station** — append to the matching file; the field
schemas are documented in each file's header comment. Top-tier flags
(`tier: "★★★ …"`, `rating >= 9`, `hub: true`) give a marker the bold ring.

## Design notes

- Typography is **Hanken Grotesk** (closest Google Font to Johnston, the TfL
  typeface); the palette leans on TfL navy `#10069f` and roundel red `#dc241f`.
- The liveability heat map and crime overlay are custom Leaflet canvas layers,
  computed live in the browser from the data files. Their tunables live in
  `CONFIG` in `js/app.js`; the liveability constants mirror
  `docs/livability.md`, which is their single source of truth.
- The base map is desaturated OpenStreetMap so the data colors carry the story.

